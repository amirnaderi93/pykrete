### 1.ii — §16 realized: `resample.agg` + `rolling.agg` + dict/callable `groupby.agg` (forward-binding amendment)

#### 1.ii.1 Correcting the stale v1.15 §16 fanout count

v1.15-spec §16 claimed **"12 match sites for `SchemaView::Grouped`"**
and used that to justify deferring resample/rolling. The count was an
**undercount**. The accurate figure on HEAD is **17
`SchemaView::Grouped` touch-sites**:
- **13** `SchemaView::Grouped` occurrences
  (`grep -rn 'SchemaView::Grouped' crates/pykrete/src | wc -l` = 13).
- **4** `Self::Grouped` arms
  (`grep -rn 'Self::Grouped' crates/pykrete/src | wc -l` = 4).

Of these 17, only **5 are compiler-forced exhaustive match arms** —
the ones that would fail to compile if a new `Windowed` variant were
added:
- `crates/pykrete/src/schema.rs:630` — `has_field`
- `crates/pykrete/src/schema.rs:638` — `field_names`
- `crates/pykrete/src/schema.rs:669` — `field_type`
- `crates/pykrete/src/schema.rs:694` — `display_name`
- `crates/pykrete/src/completion.rs:436` — completion collection

The remaining 12 are `if let` / `matches!` / constructor / test-
helper / catch-all-`other =>` sites (e.g. `expr.rs:2938`'s `other =>`
arm, `expr.rs:3070`'s let-else with an `else` fallback) that would
NOT force a change under a new variant.

**But this count only BITES under a `Windowed`-variant design, which
v1.16 is NOT taking.** Under Option B (below) no lattice variant is
added, so the 17-site fanout — 5 compiler-forced arms plus the 12
soft sites an audit would want to sweep — is avoided entirely. The
correction matters for accuracy (v1.15's "12" would have understated
the Option-A cost by 5 forced arms), but it is moot for the shipped
design.

#### 1.ii.2 D1 design = Option B (direct-chain-synthesis)

**TM-settled fork.** (`project_v26_backlog` item 11 anticipated a
`Windowed` lattice variant; the committee reversed this in favor of
the cheaper direct-chain path. The reversal is recorded here so the
v1.16 D1 developer brief starts from Option B.)

- **Recognize `df.resample("D").agg(<aggfunc>)` and
  `df.rolling(N).agg(<aggfunc>)` as CHAINS.** Synthesize `Derived`
  directly, mirroring the shipped pandas `groupby.agg("sum")` arm at
  `crates/pykrete/src/operations/expr.rs:2942-2953` (the
  `dialect == Some(Dialect::Pandas) && !after_pivot` block that
  returns `synthesize_groupby_agg_from_aggfunc(...)`). Reuse the
  v1.15 PR-D1 `resolve_override_ty` primitive for the aggregate-to-
  dtype step — D1 is that primitive's THIRD consumer, the exact
  payoff the v1.15 consolidate-before-3rd-copy rule set up.
- **NO `SchemaView::Windowed` variant this cycle.** The recognizers
  match the `.resample(...).agg(...)` / `.rolling(...).agg(...)`
  chain in a single dispatch and synthesize the result `Derived`
  without threading a window-rule through the lattice. Held-
  intermediate — `r = df.resample("D"); r.agg(...)` split across two
  statements — falls through to `Unknown` (honest silence). The
  `Windowed` lattice variant is deferred to v1.17 IF split-across-
  statements demand surfaces (§16).
- **rolling semantics.** `df.rolling(N)` is un-`Grouped`-able: it has
  no group keys and produces same-length output (a window statistic
  per row; it does not reduce rows). `df.resample(rule)` re-bins rows
  by a time rule (it DOES reduce rows) but for static column-tracking
  the modeled surface is the same — the output column set derives
  from the receiver columns via the aggfunc dtype-override, exactly
  as `groupby.agg`. D1 is therefore a NEW recognizer plus a NEW
  window-synthesis path, not a reuse of the `Grouped` reduce-by-keys
  synthesis.
- **Green-field surface.** `grep -rE "resample|rolling|Windowed"
  crates/pykrete/src` = **0** today. D1 introduces every one of these
  identifiers; there is no existing arm to regress.

Implementer picks the exact file location and helper naming. The
binding fork is: Option B (direct-chain, no lattice variant), held-
intermediate → Unknown, reuse `resolve_override_ty`.

#### 1.ii.3 D2 sub-scope (settled)

D2 extends the EXISTING pandas `groupby.agg` path — the `agg`
dispatch at `crates/pykrete/src/operations/expr.rs:1227` →
`handle_agg` (`expr.rs:2913`) → the pandas arm (`expr.rs:2950`) →
`synthesize_groupby_agg_from_aggfunc` (`expr.rs:729`) — to two more
argument shapes:
- **dict-aggfunc** — `.agg({"col": "sum"})`. The dict keys are column
  names (validate each literal key against the receiver → D0030 on a
  typo); the output columns are the dict keys with the aggfunc's
  dtype-override applied per column via `resolve_override_ty`.
- **callable-aggfunc** — `.agg(np.mean)`. A callable reference
  (`np.mean`, `sum`, `len`) mapped to a dtype-override where
  recognizable, preserving the receiver's type where not. Output
  columns = the receiver's aggregatable columns.

**DEFER list-of-aggfunc** — `.agg(["sum", "mean"])` produces
MultiIndex columns (each column × each aggfunc), which the flat
`Derived` field model does not represent. Explicit fall-through to
`Unknown` PLUS a negative-space test asserting the arm does NOT fire
and the chain stays honest. Forward-bound to v1.17 (§16).

#### 1.iii.3 inplace-guard note (PR-D2 folds it)

Two-line fall-through guards on `reset_index(drop=True, inplace=True)`
and `set_index([keys], inplace=True)`. **Multiplexer-correctness**
(`feedback_multiplexer_append_dont_change`): pandas-stubs type
`x = df.reset_index(drop=True, inplace=True)` as `x: None` (in-place
mutation returns `None`); pykrete synthesizing a `Derived` schema
OVERRIDES the engine's correct result. The guard makes pykrete fall
through on `inplace=True` so the engine's `None` stands — append,
don't change.

- **`reset_index` arm** (`crates/pykrete/src/operations/expr.rs:1691`,
  returns `Derived` at `:1698`). The inplace guard may sit at the top
  of the arm — `reset_index(drop=True)` takes no column args, so there
  is no D0030 key-existence fire to preserve. `if inplace=True →
  return None`.
- **`set_index` arm** (`crates/pykrete/src/operations/expr.rs:1718`).
  **Placement constraint:** the guard goes AFTER `report_column_refs`
  at `expr.rs:1737` (so a typoed key in `set_index(["typo"],
  inplace=True)` still fires D0030) and BEFORE the `Derived`
  synthesis at `expr.rs:1744` (so pykrete does not override the
  engine's `None`). A top-of-arm guard would skip the D0030 key-
  existence fire and is WRONG.
- **NPE-signal diagnostic** — flagging that `x` is `None` and a
  downstream `x[...]` / `x.method()` is a runtime NPE — is a v1.17
  soft-calendar item (`project_v26_backlog` item 19), NOT this cycle.
  v1.16 only stops the false synthesis; it does not add a new
  diagnostic.

## 16. Explicit v1.17+ forward-bind

The named lattice holes that remain open after v1.16. Listed here so
v1.17 spec-time committee dispatch starts with the slate already
enumerated (mirrors how v1.15 §16 forward-bound resample/rolling to
v1.16).

- **`SchemaView::Windowed` lattice variant (held-intermediate).** The
  one design v1.16 explicitly did NOT take (§1.ii.2). Needed for
  split-across-statements resample/rolling: `r = df.resample("D");
  r.agg(...)`. Would fan out the 5 compiler-forced exhaustive arms
  (§1.ii.1) plus the 12 soft `SchemaView::Grouped` sites an audit
  would sweep. v1.17 IF split-across-statements demand surfaces.
- **`expanding.agg`.** Cumulative-window semantic asymmetry vs
  resample/rolling; deliberately held back from the v1.16 bundle
  (`project_v26_backlog` item 11 note).
- **`groupby.agg` list-of-aggfunc** (`.agg(["sum","mean"])` →
  MultiIndex columns). The flat `Derived` field model can't represent
  MultiIndex columns; v1.16 falls through to Unknown with a negative-
  space test (§1.ii.3). v1.17 candidate paired with the MultiIndex
  work.
- **inplace NPE-signal diagnostic.** v1.16 stops the false synthesis
  on `inplace=True` (§1.iii.3) but does NOT flag that `x = df.op(...,
  inplace=True)` binds `None` and a downstream `x[...]` is a runtime
  NPE. v1.17 soft-calendar (`project_v26_backlog` item 19).
- **`reset_index(drop=False)` index-promotion.** Preserves the index
  AS a new column; needs index-state tracking of which column moved
  to the index at `set_index` / `groupby` time.
- **`reset_index(level=)` MultiIndex slice.** Resets one level of a
  MultiIndex, leaving others; stateful lattice work
  (`project_v26_backlog` item 13).
- **MultiIndex-on-rows.** `set_index(append=True)` /
  `reset_index(level=)` row-MultiIndex shapes.
- **`.loc` non-literal.** Multi-cycle.
- **migrate flags** (`--include-py` / `--changed-only` /
  `--dry-run-since=`). `--changed-only` / `--dry-run-since=` need a
  USER-DECISION first (§8.2 / §12) — soft-calendar note, NOT a
  binding amendment. `--include-py` is scopeable without a decision.

v1.17 spec time picks which of these bundle in based on committee
sizing.
