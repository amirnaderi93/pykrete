## 1. Theme + headline

**Theme**: cross-dialect handoff + deferred-promise closure. NOT
"Bridge to v2.0" — both agents flagged that framing as overclaim
(S round-2 critique 2.1 of their own round-1 frame; P round-1 §2a).

escalates the deprecation signal but does not ship the auto-migrator.

**Headline trust claim after v1.5**: pykrete tracks schema across the
Spark↔pandas boundary (`.toPandas()`, `spark.createDataFrame(pdf)`) at
the same depth it tracks within a single dialect. Deferred promises
close: `.loc[:, "col"]` lands (literal form), the pandas
`.head/.tail/.first` silent-terminal from the v1.4 spark-coverage audit
closes, two PR-F1 sibling-arm gates ship.

**Explicit non-claims**: no full `pykrete migrate` auto-rewriter; no
`df.query` / `df.eval` string-DSL parser; no broader pandas reshape
methods; no multi-index / dtype subtypes; no polars. All deferred with
paste-from-source grounding in §9.

v1.x throughline: v1.0 PySpark columns → v1.1 types → v1.2 lattice →
v1.3 pandas peer-dialect → v1.4 pandas depth → **v1.5 cross-dialect +
deferred-promise closure** → v2.0 alias removal.

## 2. Pillar A — cross-dialect handoff (3 PRs, may run in parallel)

PR-A1/A2/A3 touch different code surfaces and may run in parallel.

### 2.1 PR-A1 — `.toPandas()` propagation (`SparkFrame[X]` → `PandasFrame[X]`)

**Design questions answered**:

1. **Schema preservation**: yes — same `Pick[X]`-style typing carries
   across. Same shape as v1.0 `withColumn` propagation plus a dialect
   transition; architectural primitives exist.
2. **Lossy conversions** (`TimestampType` → `datetime64[ns]` UTC,
   `DecimalType` → `object`, etc.): OUT for v1.5. pykrete is a
   schema-tracker, not a type-coercion warner. Documented limitation.
3. **`.toPandas(arrow=True)` and kwargs**: same propagation; kwargs
   ignored.
4. **Round-trip** (`spark.createDataFrame(df.toPandas())`): preserves
   tags. PR-A2 re-tags PR-A1's `PandasFrame[X]` to `SparkFrame[X]`.
   Architectural property: dialect tag survives method boundaries.

**Inference site**: new `Expr::Call` arm for receiver-dialect = Spark,
method = `toPandas`. Receiver must be DataFrame-bound; otherwise fall
through cleanly.

**Negative-space tests MANDATORY per v14-rule 4**:
- `helper.toPandas()` where `helper` is not a DataFrame → no inference.
- `df.toPandas(somearg=...)` → same propagation (kwargs ignored).
- `f().toPandas()` where `f()` returns Unknown → result Unknown.
- `df.toPandas()` where `df` is already `PandasFrame[X]` → fall
  through.

### 2.2 PR-A2 — `spark.createDataFrame(pdf)` reverse path

**Schema source ordering** (v1.0 design rule applied consistently):

1. **Primary**: `schema=` keyword arg resolves to `DataFrame[X]` or
   `SparkFrame[X]` annotation. Result: `SparkFrame[X]`.
2. **Fallback**: declared annotation on `pdf` (`PandasFrame[Y]`).
   Result: `SparkFrame[Y]`.
3. **Auto-inference WITHOUT either is EXPLICITLY OUT** per the v1.3
   pandas roadmap "what we do not ship" section. Neither present →
   Unknown.

**Inference site**: new arm for receiver = SparkSession binding,
method = `createDataFrame`. Receiver-binding lookup mirrors existing
`spark.read.<format>` recognition.

**Negative-space tests MANDATORY per v14-rule 4**:
- `spark.createDataFrame(pdf)` with neither `schema=` nor `pdf`
  annotation → Unknown, no diagnostic.
- `spark.createDataFrame(rows, schema=DataFrame[X])` where `rows` is
  a list literal → `schema=` drives result.
- `not_spark.createDataFrame(pdf)` → fall through.
- `schema=` fails to resolve → fall back to `pdf` annotation per step 2.

### 2.3 PR-A3 — pandas `.head` / `.tail` / `.first` dialect-gating

Production bug from v1.4 spark-coverage audit. STANDALONE PR — fix
shape is structurally different from A1/A2.

**Current code** at `crates/pykrete/src/operations/shapes.rs:85-102`:

```rust
pub(super) fn is_terminal_method(method: &str) -> bool {
    matches!(
        method,
        // → long
        "count"
        // → list of Row
        | "collect"
        | "take"
        | "tail"
        // → None
        | "show"
        | "printSchema"
        | "explain"
        // → Row
        | "first"
        | "head"
    )
}
```

On Spark, `head`/`tail`/`first` ARE terminals. On pandas, they return
a DataFrame (sliced). pykrete currently lumps them together and drops
the dialect tag.

**Design**: refactor `is_terminal_method(method: &str) -> bool` →
`is_terminal_method(method: &str, dialect: Dialect) -> bool`. Pandas-
receiver-headed `head`/`tail`/`first` route to a pass-through arm
(`PandasFrame[X]` → `PandasFrame[X]`). Spark side unchanged.

**Sibling-arm grep target (within the terminal table itself) per
v14-rule 5**: does `count`/`take`/`collect` need dialect-splitting?
- `count`: YES on pandas (returns Series of per-column counts) but
  Series tracking is out of scope; stays terminal in this PR with a
  code comment.
- `collect`: NO — Spark-only.
- `take`: NO — exists on both, rare in practice; deferred to v1.6.
- `show`/`printSchema`/`explain`: NO — Spark-only debugging.
- `first`: shipped in PR-A3 alongside `head`/`tail`.

**Negative-space tests MANDATORY per v14-rule 4**:
- `spark_df.head()` → `Row`/Unknown (Spark terminal preserved).
- `pandas_df.head()` → `PandasFrame[X]` (dialect preserved).
- `pandas_df.head(5)` → same; positional arg ignored.
- `helper.head()` → no inference.
- `pandas_df.head().filter(...)` → filter sees `PandasFrame[X]`
  (closes the silent-terminal gap).

## 4. Pillar C — `.loc[:, "col"]` literal-form-only (PR-C)

v1.3 spec promised `.loc[:, "col"]`. v1.4 release notes demoted it to
"v1.5 tracked". A third demotion is a trust violation per P round-1
§1c; S round-2 §2.3 conceded P was correct here.

**Scope CAREFULLY** — literal form only, not a partial step to broader
`.loc`:
- IN scope: `df.loc[:, "col"]` (slice-all-rows, string-literal column).
- OUT of scope: `df.loc[mask, "col"]` (boolean-mask) → v1.6.
- OUT of scope: `df.loc[:, "a":"b"]` (column range) → v1.6.
- OUT of scope: `df.loc[idx, "col"]` (label-indexed row) → v1.x out;
  needs multi-index.
- OUT of scope: `df.iloc[...]` → v1.6.

**Implementation**: new arm in `infer_expr_type` for
`Expr::Subscript(receiver, Expr::Tuple([Expr::Slice(None,None,None),
Expr::StringLiteral(col)]))`. Receiver must be DataFrame-bound (gate
per v14-rule 4 pattern from PR-F1).

**Negative-space tests MANDATORY per v14-rule 4**:
- `df.loc[:, col_var]` (variable, not literal) → no diagnostic, fall
  through cleanly; do not invent a synthetic schema.
- `df.loc[bool_mask, "col"]` (boolean mask) → DEFER; no diagnostic.
- `df_not_frame.loc[:, "x"]` → no schema lookup.
- `df.loc[:, "col"]` where `"col"` not in `X`'s fields → D0030 fires
  (positive case).
- `df.loc[1:5, "col"]` (non-`:` slice) → DEFER; fall through.

### 5.1 D0090 strict-mode escalation

D0090 (`DataFrame[X]` deprecation) escalates `warning` → `error` when
`typeCheckingMode: "strict"` is set. Configurable in the rules block:
`"D0090": "off" | "warning" | "error"`, threaded through the existing
`apply_rules` surface. Default (non-strict): unchanged warning;
non-strict users see no behavior change. Strict mode: fires as error.
Modeled on TypeScript's `strict` family (S round-1 §2.4; P round-2
§2.4 accepted).

Message text gets explicit "this will be removed in v2.0" framing
plus a pointer to `pykrete check --report-aliases`. Paste-from-binary
in docs per v13-rule 10.

### 5.2 `pykrete check --report-aliases` flag

NEW flag on the `check` subcommand. Emits structured JSON listing
every `DataFrame[X]` annotation site with the resolved dialect at that
site (Spark / pandas / ambiguous). Does NOT rewrite source. Users
pipe to their own tooling.

Report shape:

```json
{
  "schemaVersion": "1",
  "aliases": [
    {"file": "src/jobs/sales.pyk", "line": 42, "column": 18,
     "resolvedDialect": "spark",
     "wouldBeReplacement": "SparkFrame[Sales]"},
    {"file": "src/jobs/sales.pyk", "line": 117, "column": 9,
     "resolvedDialect": "ambiguous", "wouldBeReplacement": null}
  ]
}
```

`schemaVersion` matches the JSON stability contract per
`main.rs:316-328`. `wouldBeReplacement` is `null` for ambiguous sites
— pykrete refuses to guess (v1.0 "users declare schemas" rule).

**Honest framing**: v1.5 makes the v2.0 migration **visible**. v1.6
ships the **migrator binary** (`pykrete migrate` with `--fix`,
code-action framework, in-place rewrites, dry-run).

## 6. Pillar E — synthetic-pool bound (PR-E)

I4 finding from v1.4 architecture audit. LSP memory growth on long
editor sessions (P round-1 §2e).

**Current code** at
`crates/pykrete/src/operations/context.rs:30-44`:

```rust
fn synthetic_name_pool() -> &'static Mutex<HashSet<&'static str>> {
    static POOL: OnceLock<Mutex<HashSet<&'static str>>> = OnceLock::new();
    POOL.get_or_init(|| Mutex::new(HashSet::new()))
}

fn intern_synthetic_global(name: String) -> &'static str {
    let mut pool = synthetic_name_pool().lock().expect("pool mutex poisoned");
    if let Some(existing) = pool.get(name.as_str()) {
        return existing;
    }
    let leaked: &'static str = Box::leak(name.into_boxed_str());
    pool.insert(leaked);
    leaked
}
```

Every distinct synthetic column name (`sum(amount)`, `avg(price)`,
…) leaks a `'static` string. Long LSP sessions grow unbounded.

**Design**: bounded LRU pool, 10k entries, FIFO eviction. Simpler
than the `Arc<str>` session-lifetime alternative; no LSP-event
coupling. The test-only `pool_size` view at `context.rs:46-49`
supports a size-asserting stress test. 10k is well above realistic
distinct-name counts.

## 9. Honest deferrals (paste-from-source verifications)

### 9.1 String-DSL (`df.query` / `df.eval`) → v1.6+

**Verification** — `crates/pykrete/src/sql.rs:19-20`:

```rust
use sqlparser::dialect::GenericDialect;
use sqlparser::parser::Parser;
```

Public surface wraps fragments with `SELECT ` and walks
`sqlparser::ast` for `Expr::Identifier`. SQL grammar, NOT pandas-eval.

Pandas `df.query()` uses pandas-eval (`numexpr`-influenced): backtick
quoting (`` `weird col` ``), `@variable` for Python locals,
Python-precedence `and`/`or`/`not`, row-predicate (no projection
list), method-call chains (`col.str.startswith('x')`).
`pd.DataFrame.eval()` allows assignment shapes (`new_col = a + b`) —
not a SQL statement.

S round-1 claimed "reuses existing SQL parser infrastructure"; P
round-2 §1.1 falsified against `sql.rs`; S round-2 §2.4 conceded.
Realistic budget: spec PR + 3-4 implementation PRs in v1.6+.
