## 1. Theme + headline

**Theme**: cross-dialect handoff + deferred-promise closure. NOT
"Bridge to v2.0" — both agents flagged that framing as overclaim
(S round-2 critique 2.1 of their own round-1 frame; P round-1 §2a).
v2.0's only locked commitment is `DataFrame[X]` alias removal; v1.5
adds **visibility** for migration (`--report-aliases`) but does not
escalate D0090 to error and does not ship the auto-migrator — those
land together in v1.6 (round-2 TM/user decision; rationale in §5).

**Headline trust claim after v1.5**: pykrete tracks schema across the
Spark↔pandas boundary (`.toPandas()`, `spark.createDataFrame(pdf)`) at
the same depth it tracks within a single dialect. Deferred promises
close: `.loc[:, "col"]` lands (literal form), pandas
`.head/.tail/.first` silent-terminal closes, two PR-F1 sibling-arm
gates ship.

**Explicit non-claims**: no D0090 severity change (stays warning
everywhere); no `pykrete migrate` auto-rewriter; no `df.query` /
`df.eval` string-DSL parser; no broader pandas reshape; no
multi-index / dtype subtypes; no polars. All deferred with
paste-from-source grounding in §9.

v1.x throughline: v1.0 columns → v1.1 types → v1.2 lattice →
v1.3 pandas peer-dialect → v1.4 pandas depth → **v1.5 cross-dialect
+ deferred-promise closure** → v2.0 alias removal.

## 2. Pillar A — cross-dialect handoff (3 PRs, may run in parallel)

PR-A1/A2/A3 touch different code surfaces. PR-A3 is NOT bundled with
A1/A2 — its fix shape differs (P round-2 §1.2 against
`shapes.rs:85`; S round-2 §2.2 conceded).

### 2.1 PR-A1 — `.toPandas()` propagation (`SparkFrame[X]` → `PandasFrame[X]`)

**Design**: schema preservation = yes, same `Pick[X]`-style typing
carries across (v1.0 `withColumn` shape plus a dialect transition).
Lossy conversions (`TimestampType` → `datetime64[ns]` UTC,
`DecimalType` → `object`, …) OUT for v1.5 — pykrete is a
schema-tracker, not a type-coercion warner. `.toPandas(arrow=True)`
kwargs same propagation, ignored. Round-trip
(`spark.createDataFrame(df.toPandas())`) preserves tags: PR-A1 types
the inner `df.toPandas()` as `PandasFrame[X]`; PR-A2 reads that
**inferred** type on the call-arg expression to re-tag back to
`SparkFrame[X]` (see §2.2 step 2).

**Inference site**: new arm in `column_exprs::infer_expr_type`
(`column_exprs.rs:46`), inside the `Expr::Call` branch at
`column_exprs.rs:72-…`. Resolve receiver-dialect via recursive
`infer_expr_type(&attr.value, …)` so both Name receivers and inline
subexpressions (`df.filter(...).toPandas()`) work. Receiver must be
DataFrame-bound and Spark-dialect; otherwise fall through.

**Negative-space tests MANDATORY per v14-rule 4**:
- `helper.toPandas()` where `helper` is not a DataFrame → no inference.
- `df.toPandas(somearg=...)` → same propagation (kwargs ignored).
- `f().toPandas()` where `f()` returns Unknown → result Unknown.
- `df.toPandas()` where `df` is already `PandasFrame[X]` → fall
  through.

### 2.2 PR-A2 — `spark.createDataFrame(pdf)` reverse path

**Schema source ordering** (resolve via type-of-the-argument-name,
not literal type syntax at the runtime call site — round-1 important
#4 fix):

1. **Primary**: the argument passed as `schema=` is a `Name` whose
   declared annotation is `DataFrame[X]` or `SparkFrame[X]`. Result:
   `SparkFrame[X]`. `schema=` takes a runtime `StructType` or list,
   never a type expression, so we resolve through the binding.
2. **Fallback**: declared OR inferred `PandasFrame[Y]` tag on the
   call-arg expression, resolved via recursive
   `infer_expr_type(&arg, …)` so both `Name` bindings and inline
   subexpressions (`df.toPandas()` PR-A1 has typed) are read — same
   recursion shape PR-A1 uses for receiver-dialect lookup. Result:
   `SparkFrame[Y]`. (Round-1 important #2 reconciles round-trip
   with schema-source ordering.)
3. **Auto-inference WITHOUT either is EXPLICITLY OUT** per v1.3
   pandas roadmap "what we do not ship". Neither present → Unknown.

**Inference site**: new arm in `column_exprs::infer_expr_type` for
`Expr::Call` where method = `createDataFrame`. Gated on the
PRESENCE of either (a) a `schema=` keyword arg, or (b) a call-arg
expression that types as `PandasFrame[Y]` via recursive
`infer_expr_type(&arg, …)` (the step-2 path). Receiver shape is
NOT itself a gate — there is no real SparkSession-binding lookup
in v1.5 (see B-R2-3 rationale below); the gate is one of the two
inputs above. If neither is present, fall through to Unknown.

**Why not mirror `spark.read.<format>`**: `is_spark_opaque_source_call`
at `shapes.rs:154-174` is purely STRUCTURAL — it checks
`attr.value.is_name_expr()` (line 170) and explicitly disclaims
binding lookup. It is safe because it returns `Unknown` (a safe
default); PR-A2 returns a TAG (`SparkFrame[Y]`), so a structural-
only match on `<name>.createDataFrame(pdf)` would mis-tag
`not_spark.createDataFrame(pdf)` as Spark. v1.5 scope does not
include adding binding-lookup infrastructure; PR-A2 is constrained
to the schema-source-driven path above, and binding-lookup is a
future PR if real-codebase evidence demands it.

**Negative-space tests MANDATORY per v14-rule 4**:
- `spark.createDataFrame(pdf)` with neither `schema=` nor `pdf`
  annotation → Unknown, no diagnostic.
- `spark.createDataFrame(rows, schema=schema_var)` where `schema_var:
  SparkFrame[X]` is a parameter annotation → `SparkFrame[X]`
  (annotation read through the variable binding, not literal syntax).
- `not_spark.createDataFrame(pdf)` where `not_spark` is a bound
  `Name` with no `SparkSession` annotation AND the call has NO
  `schema=` AND `pdf` has NO `PandasFrame[…]` annotation/inferred
  type → fall through to Unknown. (The gate is presence of one of
  the two schema sources, not receiver shape — this test pins that
  a missing-both case falls through cleanly.)
- `schema=` argument's variable has no resolvable annotation → fall
  back to `pdf` annotation per step 2.
- `spark.createDataFrame(df.toPandas())` → re-tags PR-A1's inferred
  `PandasFrame[X]` to `SparkFrame[X]` (round-trip regression guard).

### 2.3 PR-A3 — pandas `.head` / `.tail` / `.first` dialect-gating

Production bug from v1.4 spark-coverage audit. Standalone PR — fix
shape differs from A1/A2.

**Current code** at `crates/pykrete/src/operations/shapes.rs:85-102`:
`is_terminal_method` returns true for `count`, `collect`, `take`,
`tail`, `show`, `printSchema`, `explain`, `first`, `head`. On Spark,
`head`/`tail`/`first` ARE terminals; on pandas, they return a DataFrame
(sliced). pykrete currently lumps them together and drops the
dialect tag.

**Design**: refactor `is_terminal_method(method: &str) -> bool` →
`is_terminal_method(method: &str, dialect: Dialect) -> bool`. Pandas-
receiver-headed `head`/`tail`/`first` route to a pass-through arm
(`PandasFrame[X]` → `PandasFrame[X]`). Spark side unchanged.

**Sibling-arm classification (within the terminal table) per v14-rule 5**:
`count` stays terminal (pandas returns Series, out of scope); `collect`,
`show`, `printSchema`, `explain` are Spark-only; `take` exists on both
but rare, deferred to v1.6; `first` ships in PR-A3 alongside
`head`/`tail`. (Not a grep — the table is the closed enumeration in
`shapes.rs:85-102`; the classification IS the sibling-arm sweep.)

**Negative-space tests MANDATORY per v14-rule 4**:
- `spark_df.head()` → `Row`/Unknown (Spark terminal preserved).
- `pandas_df.head()` → `PandasFrame[X]` (dialect preserved).
- `pandas_df.head(5)` → same; positional arg ignored.
- `helper.head()` → no inference.
- `pandas_df.head().filter(...)` → filter sees `PandasFrame[X]`
  (closes silent-terminal gap).
- `pandas_df.count()` → Unknown / terminal (pandas `count()` returns
  a Series of per-column counts; Series tracking is OUT for v1.5).
  Test pins this so a future PR doesn't silently route it through
  the pandas pass-through arm. Round-1 important #5 fix.

### 3.1 PR-B1 — I1 cross-DataFrame subscript misroute (`col_refs.rs`)

The subscript arm at `col_refs.rs:286-293` IS already gated on
`ctx.lookup(name.id.as_str()).is_some()` (line 288). The bug is
ROUTING: comment at `col_refs.rs:263-267` reads "We ignore which `df`
is referenced," so `df_other["col"]` inside a method called on `df`
collects `col` against `df`'s schema, not `df_other`'s.

Fix: thread the receiver name through `collect_col_refs`'s output.
**Signature delta**: tuple `(&'a str, TextRange)` →
`(Option<&'a str>, &'a str, TextRange)`. Attribute arm
(`col_refs.rs:272-278`) and subscript arm (`:286-293`) both populate
the new `Option<&str>` field. Schema-lookup callers route to the
named receiver's schema; fall back to current-chain schema when
`None`.

**Recursion semantics**: only the two leaf arms (attribute
`col_refs.rs:272-278`, subscript `:286-293`) set the receiver-Name
to `Some(name.id.as_str())` — the receiver Name is directly bound
there. Every recursive `collect_col_refs` callsite inside this
function (verified hits at `col_refs.rs:324, 332, 338, 341, 352,
356, 362, 368, 370, 373, 376, 378, 379, 382, 383, 385, 387, 389,
394, 398-400, 404, 409, 412`) descends into expressions where the
receiver context has shifted (call args, kwargs, nested operands);
those leaves push `None`. No threading parameter is added to
`collect_col_refs`'s signature — the receiver-Name is computed
locally inside each leaf arm.

**Blast radius (multi-file per v14-rule 5)** — PR-B1 is NOT a
single-file change. Verified consumer surface on commit d6f2d0e:

- `col_refs.rs` — 5 `out.push` sites (lines 260, 276, 291, 322,
  350); the producer surface widens to the new 3-tuple. Recursion
  callsites listed above continue to thread through unchanged.
- `column_methods.rs` — Vec construction at `:37, :38, :228, :355,
  :425-426, :488, :551, :829, :982` widens to the 3-tuple type.
  `report_column_refs` signature at `:1008` updates; 7 internal
  callsites consume the new field (`:66, :70, :371, :496, :556,
  :850, :1001`).
- `strict_operators.rs` — `Vec<(&'a str, TextRange)>` parameter
  types on `string_out`/`column_out` at `:1146, :1147` widen for
  the column tuple; `string_out` is column-name-strings (no
  receiver attribution needed — keep as 2-tuple).

**Verification grep (multi-file)**:

### 5.1 `pykrete check --report-aliases` flag

NEW flag on `check`. Emits structured JSON listing every
`DataFrame[X]` annotation site with resolved dialect (`spark` or
`pandas` only — `ambiguous` is reserved for v1.6 migrator-time

to quantify migration scope before v1.6's auto-rewriter.

**Locations**: every `DataFrame[X]` annotation in analyzed user
code (function signatures, variable annotations, return types, cast
targets). Stubs / dependency files NOT reported.

Report shape:

```json
{
  "aliasReportVersion": "1",
  "aliases": [
    {"file": "src/jobs/sales.pyk", "line": 42, "column": 18,
     "resolvedDialect": "spark",
     "wouldBeReplacement": "SparkFrame[Sales]"},
    {"file": "src/jobs/sales.pyk", "line": 117, "column": 9,
     "resolvedDialect": "pandas",
     "wouldBeReplacement": "PandasFrame[Sales]"}
```

`aliasReportVersion` is payload-shape-specific, distinct from the
diagnostic JSON's `schemaVersion` at `main.rs:316-328` so the two
outputs evolve independently (round-1 minor #12). v1.5 emits only
`spark` / `pandas` for `resolvedDialect`; sites with neither

## 6. Pillar E — synthetic-pool soft cap + warn + saturate (PR-E)

I4 finding from v1.4 architecture audit. LSP memory growth on long
editor sessions (P round-1 §2e).

**Current code** at
`crates/pykrete/src/operations/context.rs:31-44`:

```rust
fn synthetic_name_pool() -> &'static Mutex<HashSet<&'static str>> {
    static POOL: OnceLock<Mutex<HashSet<&'static str>>> = OnceLock::new();
    POOL.get_or_init(|| Mutex::new(HashSet::new()))
}

fn intern_synthetic_global(name: String) -> &'static str {
    let mut pool = synthetic_name_pool().lock().expect("pool mutex poisoned");
    if let Some(existing) = pool.get(name.as_str()) {
        return existing;
    }
    let leaked: &'static str = Box::leak(name.into_boxed_str());
    pool.insert(leaked);
    leaked
}
```

Every distinct synthetic column name (`sum(amount)`, `avg(price)`, …)
leaks a `'static` string via `Box::leak`. Long LSP sessions on
adversarial inputs grow unbounded.

**Design (round-2 redesign — pre-adoption framing: graceful
degradation over correctness theater)**: keep the existing
`Box::leak`-based `&'static str` contract; add a soft cap
(configurable, default `synthetic_pool_cap: usize = 10_000`). On
reaching cap, emit a one-shot stderr warning and **saturate**
further inserts to a single static sentinel `__pykrete_pool_full__`.
Pre-cap entries still resolve correctly via the HashSet lookup
(the existing `if let Some(existing) = pool.get(name.as_str())`
arm); post-cap distinct names collide on the sentinel but the LSP
keeps running. No panic.

One-shot warning text: `pykrete: synthetic pool reached cap N,
further synthetics will not be pooled` (emitted once via an
`AtomicBool` warned-flag so we don't spam stderr on every miss).

Sentinel rationale (vs per-call `Box::leak`): a per-call leak
post-cap converts the cap from "bound the pool" to "lose the
deduplication" — same unbounded growth, just renamed. The static
sentinel preserves the bound; downstream code that consumed the
synthetic name keeps working (the string is non-empty and stable),
and any code that pattern-matches on the sentinel can detect the
saturated state if it cares.

**Rejected alternatives**:
- **Hard cap + panic**. Considered, rejected as LSP-crash
  regression vs. v1.4's leak-but-live baseline. A new panic in a
  long-running LSP is worse than the leak it replaces; pre-adoption
  users should not see the language server die on adversarial input.
- **`Arc<str>` pool with bounded insertion-ordered eviction**.
  Drops entries cleanly but requires changing the `&'static str`
  contract at every call site — wider refactor than this audit-
  debt PR justifies. Revisit if a real user trips the cap.

Test-only view at `context.rs:50` (`synthetic_pool_len`) supports a
size-asserting stress test pinning growth to one entry per distinct
name. Test plan:
1. Pre-fill the pool to cap; attempt 100 more inserts; assert
   (a) no panic, (b) `synthetic_pool_len() == cap`, (c) the warning
   was emitted exactly once.
2. Assert pre-cap entries still resolve correctly (re-lookup by
   original name returns the original `&'static str`, not the
   sentinel).
3. Assert post-cap inserts return the sentinel `__pykrete_pool_full__`.
