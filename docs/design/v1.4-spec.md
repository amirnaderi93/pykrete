# v1.4 spec — pandas depth, type-tracking, and checker bug closures

**Status**: settled v1.4 spec. First PR of the v1.4 cycle.
**Predecessors**: `pandas-support.md` (v1.3 settled spec),
`spark-coverage.md` (Spark coverage reference shape).

---

## 1. Theme + headline

v1.4 is **depth on pandas**: match the PySpark donor breadth that
v1.0 established and close the type-tracking gap v1.3 deferred. The
v1.3.0 trust claim is "we check the six pandas dispatched operations
end-to-end"; the v1.4.0 trust claim is "we check pandas usage across
the dominant pandas stack and we track dtypes through those
operations."

Target headline at tag time:

| Metric | v1.3.0 | v1.4.0 target |
|---|---|---|
| Donors in cross-codebase suite | 10 | 17 |
| Donors with pandas coverage | 3 | 10 |
| Total probes (RESOLVES + EXPECTS + TYPE-IS) | 149 | ~200+ |
| Workspace tests | 1290+ | 1290+ baseline + new tests per §4 bug |
| Pandas `PROBE-TYPE-IS` markers | 0 | ≥3 per pandas donor (≥30 total) |

These are commitments to honesty about scope, not to LOC; the
implementation PRs determine actual sizes.

## 2. Donor expansion plan

Seven new pandas-heavy donors. Per donor we specify: rationale,
upstream pin target, expected fixture density, which of the six v1.3
dispatched operations the fixture exercises, what `PROBE-TYPE-IS`
markers will assert. All dtype claims must cite the upstream `dtypes`
declaration or schema source (v13-retro rule 4a).

### scikit-learn (MIT)

Industry standard for ML preprocessing; `sklearn/preprocessing/data.py`
and `sklearn/utils/validation.py` show canonical "pandas in, ndarray
out" patterns alongside pandas-native transforms. High recognition.

- **Pin**: `1.5.x` tag at v1.4 work start.
- **Fixtures**: ~3–5 annotated + ≥2 negative.
- **Operations exercised**: `df[col_list]`, `df[mask]`, `df.rename`,
  `df["new"] = expr`.
- **TYPE-IS**: `float64` columns selected from a scaler input
  retain `ColumnType::Double`; `int64` index/label columns retain
  `ColumnType::Long` after `df[["a","b"]]`.

### statsmodels (BSD-3)

Statistical modeling with pandas-native idioms throughout
`statsmodels/regression/linear_model.py`. Exercises numeric dtype
preservation through `df.merge` and `df[mask]`.

- **Pin**: `0.14.x` tag.
- **Fixtures**: ~3 annotated + ≥1 negative.
- **Operations exercised**: `df.merge`, `df[mask]`, `df[col_list]`.
- **TYPE-IS**: join-key column type survives `.merge`; `float64`
  regressor columns preserved through boolean-mask filtering.

### pandera (MIT)

Sibling project that validates pandas schemas at runtime. Selecting
pandera as a pykrete donor has unusual trust signal: pykrete is the
static peer to pandera's runtime checks.

- **Pin**: `0.20.x` tag.
- **Fixtures**: ~3 annotated + ≥1 negative.
- **Operations exercised**: `df.rename`, `df["new"] = expr`,
  `df.drop(columns=[…])`.
- **TYPE-IS**: renamed-column type tracks through `df.rename`;
  dtype-mismatch on assignment fires D0084.

### Great Expectations (Apache 2.0)

Data-quality framework, pandas-first at the core. Exercises the full
six-operation surface in a single donor.

- **Pin**: `1.0.x` tag.
- **Fixtures**: ~4–5 annotated + ≥2 negative.
- **Operations exercised**: all six.
- **TYPE-IS**: dtype preservation through chained
  filter→select→assign; `D0030` on a typo in an expectation column
  reference.

### prophet (MIT, Meta)

Time-series forecasting; pandas end-to-end with the canonical `ds`
(timestamp) + `y` (float64) schema. Tests `ColumnType::Timestamp`
and `ColumnType::Double` propagation through `df.merge` on timestamp
keys.

- **Pin**: `1.1.x` tag.
- **Fixtures**: ~3 annotated + ≥1 negative.
- **Operations exercised**: `df.merge`, `df.rename`,
  `df["new"] = expr`.
- **TYPE-IS**: `ds: datetime64[ns]` survives `df.merge`;
  `y: float64` survives through forecast-frame assembly.

### dask (BSD-3)

Distributed pandas. dask DataFrames mirror the pandas API; the
fixture asserts pykrete's pandas dispatch fires on dask code that
re-exports pandas idioms unchanged.

- **Pin**: `2024.x` release.
- **Fixtures**: ~3 annotated + ≥1 negative.
- **Operations exercised**: `df[col_list]`, `df[mask]`, `df.drop`,
  `df.merge`.
- **TYPE-IS**: partition-column dtypes propagate through chained
  `df[mask]` filters; `D0030` on a typo in a `df[["a","b"]]`
  projection.

### xarray (Apache 2.0)

Pandas-adjacent multidimensional library; exercises pandas
conversions (`.to_dataframe()` / `.from_dataframe()`).

- **Pin**: `2024.x` release.
- **Fixtures**: ~2–3 annotated + ≥1 negative.
- **Operations exercised**: `df.rename`, `df[col_list]`.
- **TYPE-IS**: pandas DataFrames built from xarray Datasets retain
  declared dtypes through subsequent `df.rename` and `df[col_list]`.

## 3. PROBE-TYPE-IS extension design

This closes **pykrete-tests#14**.

### Current state

`scripts/probes.py::_first_dataframe_param` matches only
`DataFrame[X]`. Pandas-annotated parameters using `PandasFrame[X]`
are invisible to the TYPE-IS recognizer, so today there are zero
positive pandas TYPE-IS probes (deliberate v1.3 deferral per
`pandas-support.md` §11).

### Extension

Widen `_first_dataframe_param` to also match `PandasFrame[X]` and
`SparkFrame[X]` — a name-set widening parallel to v1.3 piece (a)'s
extension of `dataframe.rs::recognize`. Implementation owns sizing.

### Synth shape for pandas TYPE-IS

The Spark TYPE-IS synth wraps the column reference in
`df.select(col("x") + lit(1))` to route through D0081's
arithmetic-result checker. **Decision**: for `PandasFrame[X]`, the
synth uses a pandas-native shape:

```
result = df[["x"]]
```

and asserts the inferred dtype of the projected single-column series
matches the claimed TYPE-IS dtype. This routes through the v1.3
column-projection dispatch row (`df[col_list]` → `Pick[X, "x"]`),
reuses the existing dtype-tracking path, and does not require a
pandas-side D0081-equivalent route. The Spark synth stays unchanged.

Rationale: pandas does not have a `lit`-style literal-promotion
surface mirroring Spark's `col(…) + lit(1)`. Forcing the Spark synth
onto pandas would introduce a fake idiom into fixtures. The
pandas-native projection shape is what real users write.

### Example markers (one per pandas donor)

- **scikit-learn**: `# PROBE-TYPE-IS: df["feature_0"] :: float64`
- **statsmodels**: `# PROBE-TYPE-IS: df["beta"] :: float64`
- **pandera**: `# PROBE-TYPE-IS: df["validated_at"] :: datetime64[ns]`
- **Great Expectations**: `# PROBE-TYPE-IS: df["row_count"] :: int64`
- **prophet**: `# PROBE-TYPE-IS: df["yhat"] :: float64`
- **dask**: `# PROBE-TYPE-IS: df["partition_id"] :: int32`
- **xarray**: `# PROBE-TYPE-IS: df["time"] :: datetime64[ns]`

## 4. Checker bug closures (three deliverables, one PR)

Three bugs surfaced during the v1.3 audit cycles. PR-B bundles all
three with one PROBE-EXPECTS fixture per bug. v13-retro rule 1: the
brief must instruct "grep all sites of pattern X" per bug.

### Bug 1 — Registry-call §10 widening edge case (architecture IMP-1)

**Symptom**: `util(df["typo"])` where `util` is in the registry but
has no `DataFrame[X]`-typed parameter silently passes. The bare
`df["typo"]` should fire D0030 (per `pandas-support.md` §10), but
the registry-call gate short-circuits before §10 fires.

**Fix — decision**: **always walk args and make
`check_one_call_arg` idempotent.** The alternative (tighten
`is_registry_function_call` to require ≥1 `DataFrame[X]`-typed param)
was rejected because it shifts the silent-skip from one gate to
another. The idempotent-walk mirrors v1.3 piece (b): walk
unconditionally and let per-arg checks decide. v13-retro rule 8:
grep for stale comments referencing the old gate.

**Test**: PROBE-EXPECTS exercising `util(df["typo"])` with `util` as
a non-frame-typed helper; assert D0030 fires on `"typo"`.

### Bug 2 — `inherited_dialect` walks Subscript / Named / walrus receivers (architecture FU-3)

**Symptom**: `(pdf := build()).rename(...)` and `df_list[0].merge(...)`
lose the `PandasFrame[X]` dialect tag because the walker in
`driver.rs:114-130` only recognizes `Expr::Name` and
`Expr::Attribute`. Walrus-bound and subscript-indexed bindings fall
through to the Spark default.

**Fix**: extend the `driver.rs:114-130` match to walk
`Expr::Subscript` (recurse into `subscript.value`) and `Expr::Named`
(walrus, recurse into `named.value`). For Subscript, dialect inherits
from the bottom receiver — parallel to chained method calls today.
v13-retro rule 1: grep all `inherited_dialect` sites.

**Test**: PROBE-EXPECTS fixtures for both walrus and
subscript-indexed shapes; assert pandas dispatch fires (e.g., D0030
on a typo in `.rename(columns={…})`).

### Bug 3 — `df.transform(helper)` dialect preservation

**Symptom**: pandas `.transform(helper)` callback drops the
`PandasFrame[X]` dialect tag on the bound helper's parameter. The
helper sees a frame-typed slot with `Dialect::Spark` (default), so
pandas-side dispatch is treated as Spark and skips or misfires.

**Fix**: in the callback-binding code path, propagate the receiver's
dialect onto the bound parameter — same way v1.3 piece (a) attaches
dialect at initial annotation recognition. v13-retro rule 1: grep
all callback-binding sites.

**Test**: PROBE-EXPECTS exercising `pdf.transform(helper)` where
`helper(p: PandasFrame[Schema])` does a pandas-only op; assert pandas
dispatch fires inside `helper`.

### v13-retro rule 7 applied

All three bugs are **PRE-EXISTING** on `main` at v1.3.0 tag, surfaced
by v1.3 audits but deferred from v1.3 scope. PR-B closes them in
v1.4. The PR brief must mark each as PRE-EXISTING so the reviewer
does not treat them as introduced regressions.

## 5. Standalone bug-fix PR scope (PR-D)

Three small fixes that don't fit the PR-B bundle. Each closes a
tracked issue.

- **pykrete.json config-discovery walk-from-file-path** (closes
  **#98**): config discovery walks from CWD today, breaking
  workflows that invoke pykrete on absolute file paths from outside
  the project. Fix: walk from the file's parent dir upward.
- **D0090 bare-DataFrame spec amendment** (closes **#99**):
  `pandas-support.md` §6 reserved D0090 for the `DataFrame[X]`
  subscripted alias case but did not specify the bare `DataFrame`
  (no subscript) emission shape. Amend the spec and align the
  checker.
- **Canonical-name migration sweep on remaining surfaces** (closes
  **#97**): residual `DataFrame[X]` references in docs/code comments
  not caught by the v1.3 PR-D sweep. v13-retro rule 2: brief lists
  trust-claim AND teach-by-example surfaces explicitly.

## 6. Probe coverage tightening

Three discrete items, sized for inclusion in PR-C-1/2/3 rather than
a standalone PR:

- **Rewrite vacuous probe `spark-test-df-drop-left-join-key`**. The
  v1.3 probe asserts a behavior the checker silently passes either
  way; v1.4 rewrites it to a falsifiable shape exercising join-key
  drop semantics.
- **Add `probes_negative/` fixtures to dbt-spark + python-deequ** —
  the two v1.3 donors with zero negative coverage. At least one
  negative fixture per donor exercising a D-code the donor's
  positive fixtures rely on.
- **Add PROBE-TYPE-IS markers to all 7 new pandas donors**. Depends
  on PR-A merging first. Markers ship in PR-C-1/2/3 alongside the
  donor fixtures.

## 7. v1.4 deferral list

Carried forward from v1.3 §11 and freshly added:

- **Cross-dialect handoff annotations** (`.toPandas()` / `.toSpark()`
  / `pd.DataFrame.from_records(...)`) — v1.5.
- **`df.query("…")` / `df.eval("…")` mini-DSL parsing** — v1.5. Q10
  in v1.3 reserved this for v1.4 but v1.4's scope is depth on what
  we already check; the string-fragment DSL parser is its own design
  surface. Re-deferred with explicit acknowledgment.
- **Broader pandas method modeling** (`pivot_table`, `groupby.agg`,
  `melt`, `stack`/`unstack`, `reset_index`, `set_index`) — v1.5.
- **Pandas multi-index support** — v1.5+.
- **Numeric subtype distinguishability** beyond v1.3 widening — still
  deferred from v1.0.
- **Pandas-on-Spark API (`pyspark.pandas`)** — deferred until user
  demand.
- **polars** — v1.6+; separate dialect, not gated on pandas.
- **Cross-dialect union annotations** (`SparkFrame[X] | PandasFrame[X]`)
  — re-deferred from v1.3 §3 to v1.5+.
- **Ordered `CategoricalDtype(ordered=True)`**, **tz-aware
  `datetime64[ns, tz]`**, **`timedelta64[ns]` / `IntervalDtype`** —
  all re-deferred from v1.3 §4 to v1.5+.

Re-deferring v1.3-deferred items requires v1.4 docs to update
"deferred to v1.4" wording so users aren't promised features that
v1.4 doesn't ship.

## 8. PR sequence

```
PR-1 (this PR) — v1.4 spec (docs/design/v1.4-spec.md)
PR-A          — probes.py TYPE-IS recognizer extension (closes pykrete-tests#14)
PR-B          — 3 checker bugs bundled (§4)
PR-C-1/2/3    — pandas donor expansion (2–3 donors per PR; §2)
PR-D          — standalone fixes (#97 + #98 + #99)
PR-E          — trust-claim migration + roadmap page in docs-site
[Re-audit cycle: 4 auditors in parallel — v13-retro rule 6]
[Followups if needed]
[Tag v1.4.0]
```

Ordering rationale:

- **PR-A first** so PR-C-1/2/3 can ship TYPE-IS markers from the
  start rather than refactoring fixtures after the fact.
- **PR-B before PR-C** so donor fixtures aren't sitting on top of
  silent dispatch bugs that might mask real findings.
- **PR-D parallelizable** with PR-C; doesn't touch donor surfaces.
- **PR-E gates the tag** per v1.2/v1.3 trust-claim discipline: no
  silent deployment window between code ship and copy update.
- **Re-audit cycle** mandatory before tag (v13-retro rule 6).

## 10. Stability surface (v1.4 additions)

v1.4 adds no new stable annotation forms and no new D-codes.

- **PROBE-TYPE-IS extension** is test infrastructure; no
  user-visible checker change.
- **Checker bug closures (§4)** are SemVer-minor under the
  `tighteningDiagnostics` policy: new firing positions for existing
  D-code identities. The v1.4 CHANGELOG carries a "Tightened
  coverage" bullet per v1.3 §10 precedent.
- **Donor expansion** is external; no user-visible API change.
- **Dtype mapping table** is not extended; any new mapping lands
  in v1.5+.
