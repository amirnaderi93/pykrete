## What you're seeing

Every keystroke (debounced ~300 ms) runs the source through pykrete's
single-file analyzer. Diagnostics show up as squiggles in the editor
and as one-liners in the panel below — each carrying pykrete's
`D\d\d\d\d` code and rule name.

The playground wires pykrete into Monaco for the IDE features that
matter on a `.pyk` file:

- **Schema-aware diagnostics.** Column typos, unknown schemas, type
  mismatches, and the rest of the `D00xx` rule surface — same engine
  the VS Code extension runs.
- **Hover.** Hover a Schema class name to see its fields; hover a
  `SparkFrame[X]`- or `PandasFrame[X]`-typed identifier (or a legacy
  `DataFrame[X]`) to see the bound schema; hover a Spark method
  (`sales.select`, `F.sum`) to see its real pyspark signature and
  docstring summary.
- **Completion.** Type a column name inside `col("…")` to get
  pykrete's column suggestions from the bound schema. Type `sales.`
  on a `SparkFrame[Schema]`-typed local to get the DataFrame method
  surface; `F.` to get `pyspark.sql.functions`; `.groupBy("…").` to
  get GroupedData methods. The Spark suggestions are generated at
  build time from a real pyspark install — see
  `docs-site/scripts/gen-pyspark-symbols.py` in the repo.
- **Go-to-definition.** Cmd/Ctrl+click (or F12) on a `SparkFrame[X]`,
  `PandasFrame[X]`, or (deprecated) `DataFrame[X]` reference to jump to
  `class X(Schema):`.

## What's NOT here

This is a single-file pykrete sandbox. Scope-wise:

- **No project-wide Python type checking.** The playground runs
  pykrete's schema checker plus the static PySpark-symbol layer
  (hover, completion, go-to-def on `sales.select`, `F.sum`, etc.).
  General Python typing — `int` / `str` flow, third-party library
  inference, your own imports — is not validated here. For that,
  install the [VS Code extension](/pykrete/getting-started/install/):
  pykrete runs alongside basedpyright (or pyright), so you get both.
- **No cross-file resolution.** Multi-file imports, project
  configuration, and the `.pyk-import` mechanism need real file
  system access — use the CLI for those.
- **Pre-declared globals.** `Schema`, `DataFrame`, `col`, `F`, and
  the lowercase PySpark-style type aliases (`string`, `double`,
  `long`, …) are pre-declared in the playground so you can start
  typing without import boilerplate. Real projects use explicit
  imports — see the [Install](/pykrete/getting-started/install/)
  page.

## Limits

- **No share-via-URL yet.** Refresh discards your edits. Bookmarkable
  snippet URLs are on the roadmap.
- **Desktop-first.** Monaco editor is hard to use on a phone; the
  diagnostics list is still useful on small screens, but typing is
  not.
- **Cold-start bundle.** Monaco loads from a CDN (~2 MB); pykrete-wasm
  is a few hundred KB and loads on demand when this page mounts.
  Other pages on the docs site are unaffected.

## Want it locally?

pykrete is a single native binary (no Python runtime; not on PyPI).
Pick whichever install fits your setup:

```bash
# macOS / Linux — Homebrew
brew install amirnaderi93/pykrete/pykrete

# Any platform with a Rust toolchain
cargo install --git https://github.com/amirnaderi93/pykrete pykrete
cargo install --git https://github.com/amirnaderi93/pykrete pykrete-lsp
```

Windows installs from the `.msi` attached to each [release](https://github.com/amirnaderi93/pykrete/releases/latest). Then check a file:

```bash
pykrete check path/to/your/file.pyk
```

For live diagnostics in your editor, install the **pykrete** VS Code
extension from the [Visual Studio Marketplace](https://marketplace.visualstudio.com/items?itemName=amirnaderi.pykrete) or [Open VSX](https://open-vsx.org/extension/amirnaderi/pykrete) (Cursor, VSCodium,
code-server, Theia). The [Install](/pykrete/getting-started/install/)
page covers every install path, Neovim / Helix / Emacs setup, and
project configuration.
